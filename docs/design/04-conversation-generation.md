# 04 会話生成システム設計書

## 1. 要件

| 要件 | 対応する節 |
|---|---|
| 会話は毎回異なる。固定の台本を繰り返さない | §4、§5 |
| 自然な会話。話し手の性格を保つ | §3、§6 |
| プレイヤーを不自然に誘導しない。会話中に評価や助言を挟まない | §6 |
| 重要情報は出題前に確定する | §2、§7 |
| あいまいな出題で失敗させない | §7 |

## 2. AI の役割分担

4つの役を、**別々の指示・別々の文脈**で動かす。互いの内部情報は見せない。

| 役 | 仕事 | いつ動くか | 見えるもの |
|---|---|---|---|
| **構成役** | シナリオ（事実の表、話し手、台本、評価基準票、問い返し）を作る | 遭遇の前 | シナリオの種、最近の出題の概要 |
| **検品役** | 台本だけを読んで情報を取り出す。評価基準票と突き合わせてあいまいさを見つける | 構成の直後 | 台本のみ（評価基準票は見ない） |
| **会話役** | プレイヤーの聞き返しに、話し手として答える | 会話中 | 話し手の設定、台本、話し手の知っていること・知らないこと。**重要度と罠の意図は見えない** |
| **評価役** | 実際の発言とプレイヤーの回答を照合する | 回答の後 | 封印した評価基準票、発話記録、確定した回答（[05](05-ai-evaluation.md)） |

会話役と評価役は完全に分ける。会話役は評価の存在を知らず、評価役は会話に参加しない。

## 3. 会話の進め方の方式

| 方式 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A: 完全即興 | 会話役がその場ですべて話す | 最も自由 | 最重要の情報を言い落とす・あいまいに言うおそれがあり、事前の検品ができない。毎回の応答に遅延と料金がかかる |
| B: 完全台本 | 一方的な語りを事前に作る。聞き返せない | 検品が完全。遅延なし | 会話にならない。確認する力を鍛えられない |
| **C: 台本先行＋即興応答（採用）** | 話の本筋は事前に作って検品する。聞き返しにだけ会話役がその場で答える | 公平性を事前に保証できる。音声を事前に合成できる。聞き返しもできる | 聞き返しへの応答だけは事前に検品できない（§6 と [05](05-ai-evaluation.md) §3 で対処） |

C を採用する。台本は**1回限りの使い捨て**であり、同じプレイヤーに二度出さない。固定の台本を繰り返す設計ではない。

### 会話の流れ

1. 話し手が台本の一区切りを話す。
2. 区切りごとに短い間がある。プレイヤーは黙って待つ、相槌を打つ、聞き返す、のいずれかを選ぶ。
3. 聞き返しがあれば、会話役が話し手として答える。その後、本筋に戻る。
4. 台本が終わると会話が終わる。シナリオによっては、立ち去るときに追い声がある。

## 4. 毎回違う会話を作る方法

Fable 5.2 は `temperature` などの乱数パラメータを受け付けない（[00](00-overview.md) §3.1）。同じ指示を繰り返すと似た話になりやすい。そのため、**多様性はプログラム側の乱択で作り、AI には組み合わせの肉付けを任せる。**

### シナリオの種

プログラムが、次の軸からそれぞれ値を選んで種を作る。

| 軸 | 例 |
|---|---|
| 題材 | 頼みごと、言づて、約束、道案内、証言、噂、警告、取引の条件、手順の説明 |
| 場面 | 地域、場所、時刻、天候、話し手の状況（急いでいる、作業中、歩いている） |
| 話し手の性格と話し方 | 回りくどい、早口、寡黙、脱線が多い、言い直しが多い、結論から話す、結論を最後に言う |
| 情報の構造 | 順序、後出し、訂正、条件、例外、伝聞の入れ子、複数の話し手 |
| 罠の型 | §5 の表から0〜3個。0個（素直な会話）を2〜3割 |
| 固有の値 | 人名、地名、日数、時刻、数量、品物。**プログラムが語彙表から選ぶ** |
| 難易度 | [02](02-game-system.md) §8 の各要素 |

固有の値をプログラムで選ぶ理由は2つある。AI は同じ名前や数を選びがちであること。そして、音の似た名前や読み誤りやすい語を、語彙表の段階で排除できること。

### 重複の防止

- 構成役に、そのプレイヤーの直近の出題の概要（題材・構造・罠の型・固有の値）を渡し、重ならないように作らせる。
- 生成後に、プログラムで過去の出題との類似を調べる（軸の組み合わせの一致、文の重なり）。似すぎていれば作り直す。
- 語彙表と軸の値は、運用しながら増やす。

### 時や数の表現

この世界独自の難解な時刻制度は作らない。「明後日の朝」「三日後の夕方」「鐘が四つ鳴る頃」のように、聞いてすぐ意味が取れる表現に限る。訓練の対象は受信であり、暗号解読ではない。

## 5. 罠の型

罠とは、解釈を早く閉じた人が誤るように作られた、情報の構造である。話し手が嘘をつくことではない。現実の会話に普通にある形だけを使う。

| 狙う能力 | 罠の型 | 例 |
|---|---|---|
| 最後まで聞く | 文末での反転 | 「山寺へ届けてほしい、と言おうと思ったが、やはり社のほうへ」 |
| | 後出しの訂正 | 「明日だ。……いや、明後日だった」 |
| | 末尾の条件 | 「ただし、雨なら行かなくていい」 |
| | 追い声 | 立ち去るときに「そうだ、もう一つ」 |
| 補完しない | 欠けた項目 | 届け先は言ったが、いつまでにとは言わない |
| | ありがちな筋書き | よくある展開に見えて、肝心の一点だけ言われていない |
| 先読みしない | 途中での転回 | 断る話に聞こえて、最後は引き受ける |
| | 似た前例 | 前の相手と似た話だが、一点だけ違う |
| 事実と推測の区別 | 話し手の推測 | 「たぶん昼には着くと思う」 |
| | 伝聞 | 「橋は直ったと、誰かが言っていた」 |
| 矛盾・不足に気づく | 食い違い | 前半は「三人」、後半は「四人」。訂正の言葉はない |
| | 不足 | 期限は言ったが、場所を言っていない |
| 不明を不明と認識する | 言われていない事柄の質問 | 問い返しで、会話になかったことを訊かれる |
| 確認する | 確かめれば解ける | 食い違いや不足は、聞き返せば話し手が答える |
| 話に沿って返答する | 求めのずれ | 助言ではなく、ただ伝言を頼んでいる |

**同じ弱点を試すときも、題材・人物・構造・固有の値は別のものにする。** 罠の型は同じでも、話としては別物になる。

## 6. 会話役の規則

会話役（聞き返しへの応答）には次を守らせる。

| 規則 | 内容 |
|---|---|
| 性格を保つ | 話し方、語彙、態度を台本と同じにする |
| 事実の表に従う | 知っていることは訊かれたら答える。知らないことは「知らない」と言う。表にない事実を作らない |
| 誘導しない | 何が重要かを示唆しない。「よく聞いて」「ここが大事」などと言わない |
| 評価しない | 聞き方の良し悪しに触れない。助言しない |
| 誤った復唱は訂正する | 人として自然な範囲で訂正する。これは誘導ではなく、確認への正当な応答である |
| 役から出ない | 世界の外の話題には、話し手として受け流す |
| 短く答える | 聞き返しへの答えは1〜3文 |

会話役には重要度と罠の意図を渡さない。知らないものは漏らせない。

聞き返しへの応答は事前に検品できない。そこで、応答で話した内容はすべて発話記録に残し、会話終了時の突き合わせ（§7 の4）の対象にする。応答が事実の表と食い違った場合は、関係する項目を無効にする。

## 7. 公平性を保証する工程

| 順 | 工程 | 内容 | 不合格のとき |
|---|---|---|---|
| 1 | 構成 | 構成役がシナリオを作る。最重要の情報素片には読み仮名を付ける | — |
| 2 | 形式の検査（プログラム） | 必須項目、読み仮名、禁止語、音の似た固有名の同居、長さ | 作り直す |
| 3 | 解答可能性の検品 | 検品役（複数回、独立）が台本だけから情報を取り出す。全員が評価基準票と一致するか。「言われていない」項目を誰かが「言われた」と読まないか | あいまいな項目があれば作り直す |
| 4 | 音声の検品 | 合成した音声を認識し直し、最重要の語の読みが意図通りかを確かめる（[06](06-voice-system.md) §5） | 合成し直す。直らなければシナリオを捨てる |
| 5 | 発話との突き合わせ | 会話終了時に、実際の発話記録と評価基準票を照合する。裏付けのない項目は無効にする | 最重要の項目がすべて無効なら無効試合 |
| 6 | 封印 | 評価基準票を確定し、要約値と時刻を記録する | — |

工程1〜4は、プレイヤーが話し手に会う前に終わらせる。

## 8. 題材の制限と拒否への対処

- 扱う題材は日常の用事に限る。毒、病の広がり、武器の作り方などは扱わない。物語上も不要であり、Fable 5.2 の安全分類器による拒否を避けるためでもある。
- 拒否（`stop_reason: "refusal"`）が返った場合に備え、代替モデルへの自動切替を設定する。それでも失敗したら、別の種で作り直す。
- 実在の人物・団体・既存作品の固有名は、語彙表の段階で排除する。

## 9. 生成の時機と在庫

| 方式 | 内容 | 料金 | 待ち時間 |
|---|---|---|---|
| 都度生成 | 遭遇のたびに作る | 最も高い | 生成と検品に時間がかかる。探索中に先行して作る必要がある |
| 個人別の先行生成 | そのプレイヤー用に、数本先まで作っておく | 都度生成と同じ | なし |
| **共有の在庫** | 事前に大量に作り、検品と音声合成を済ませておく。各プレイヤーには、まだ見ていないものを1回だけ出す。一定回数使われたら廃棄する | 複数人で割るので最も安い。バッチ処理（半額）も使える | なし |

共有の在庫でも、プレイヤーにとっては毎回初見である。ただし「毎回生成する」という仕様の文言と解釈が分かれるため、**採否の判断を仰ぐ（[00](00-overview.md) Q2）**。推奨は、共有の在庫を基本とし、弱点に特化した出題が在庫にない場合だけ都度生成する併用である。

個人利用（プレイヤーが1人）の場合、在庫の共有による節約は起きない。料金の比較は [07](07-unity-architecture.md) §7。
