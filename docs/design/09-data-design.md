# 09 データ設計

今回は設計のみであり、表の定義やコードは書かない。ここでは、何を・どこに・どれだけの期間持つかを定める。

## 1. 保存場所の方針

| 場所 | 置くもの | 理由 |
|---|---|---|
| サーバーのデータベース | 利用者、進行、試練の記録、評価基準票、判定、弱点の記録、シナリオの在庫 | 判定と進行の正本を守る。機種をまたいで引き継ぐ |
| サーバーのファイル保管 | 合成した音声、判定の監査記録 | 大きなデータ。配信しやすい |
| 端末 | 設定、進行の写し（表示用）、取得済みの音声、取得済みの地域データ | 起動を速くする。通信量を減らす |
| リポジトリ | 語彙表、シナリオの軸の定義、罠の型の定義、AI の指示文、判定の規則表、正解集 | 版管理し、変更を検定する |

データベースの製品は第2段階で決める（候補: PostgreSQL）。個人利用の試作では、サーバーを手元の PC で動かし、ファイルや組み込み型のデータベースで代用できる。

## 2. データの種類

### 利用者に関するもの

| データ | 主な内容 |
|---|---|
| 利用者 | 識別子、作成日時、引き継ぎ用の連携情報（任意） |
| 設定 | 受信の方式、選んだ声、話す速さ、字幕、入力方法、画質、同意の記録 |
| 進行 | 到達した地域、ともした結び灯籠、現在の道行きと灯火、主の試練の達成 |
| 聴き帳 | 能力ごとの試行数と成功数、ミスの種類ごとの回数、罠の型ごとの成績、最近の傾向 |
| 出題履歴 | 出題済みのシナリオの識別子、種の軸の値、固有の値。重複の防止に使う |

### シナリオに関するもの

| データ | 主な内容 |
|---|---|
| シナリオの種 | 題材、場面、話し手の性格、情報の構造、罠の型、固有の値、難易度、乱数の種 |
| 事実の表 | 話し手が知っていること、知らないこと、訊かれたら答えること |
| 台本 | 区切りごとの文、読み仮名、話者、間、追い声 |
| 評価基準票 | 情報素片ごとの項目（[05](05-ai-evaluation.md) §2）、問い返しの一式 |
| 検品の記録 | 各工程の合否、検品役の取り出し結果、不合格の理由 |
| 音声 | 区切りごとの音声ファイル、声の種類、検査で確かめた読み |
| 在庫の状態 | 作成日時、使用回数、廃棄の予定、生成に使ったモデルと指示文の版 |

### 試練の記録

| データ | 主な内容 |
|---|---|
| 試練 | 利用者、シナリオ、型、稽古か本番か、開始と終了の日時、結果、格 |
| 発話記録 | 実際に流れた話し手の文、聞き返しとその応答、時刻 |
| 封印 | 封印した評価基準票の内容、要約値、封印の時刻 |
| 回答 | 確定した申し送り（文、確度の印、宣言）、問い返しへの回答、入力方法 |
| 判定 | 情報素片ごとの状態、引用、確信の度合い、説明、適用した規則、A・B・C の別 |
| 監査記録 | 評価の入力と出力の全文、モデルと指示文と規則表の版、2回目の評価、物言いとその結果 |
| 利用量 | 呼び出しごとのトークン数、音声の文字数と秒数、概算の金額 |

### 運用に関するもの

| データ | 主な内容 |
|---|---|
| 正解集 | 人が正解を付けた「シナリオと回答」の組。評価役の検定に使う |
| 音声の試験集 | 音声認識の検証用の録音と正解の文 |
| 版の記録 | 指示文、規則表、語彙表、モデルの版と、検定の結果 |

## 3. 整合性の規則

| 規則 | 内容 |
|---|---|
| 封印の順序 | 封印の時刻は、必ず回答の確定より前。逆なら判定を無効にする |
| 封印の不変 | 封印後の評価基準票は変更しない。変更できるのは項目を無効にする操作だけで、記録を残す |
| 引用の実在 | 判定の引用は、発話記録と回答に実在する文字列でなければならない |
| 一度きり | 同じシナリオを同じ利用者に二度割り当てない |
| 正本 | 進行と判定はサーバーが正。端末の写しと食い違えばサーバーに合わせる |
| 無効試合 | 無効試合の記録は残すが、成績と弱点の記録には数えない |
| 版の追跡 | すべての判定から、使ったモデル・指示文・規則表の版をたどれる |

## 4. 保持期間と削除

期間は仮の値。対象地域の法令と [00](00-overview.md) Q1・Q10 の回答に合わせて確定する。

| データ | 保持 | 備考 |
|---|---|---|
| 利用者の音声 | **保存しない**（既定） | 精度検証への提供に同意した場合のみ、期間を区切って保存 |
| 回答文、発話記録 | 90日 | 分析の見直しと物言いのため。その後は集計値だけ残す |
| 監査記録 | 90日 | 誤判定の調査のため |
| 聴き帳、進行 | アカウントがある間 | — |
| 使用済みシナリオと音声 | 分析から参照される間 | 聞き直しの機能のため |
| AI 提供者側の保持 | 30日 | Fable 5.2 の利用条件。こちらでは短縮できない |

- 利用者は、設定画面から自分のデータの削除を求められる。
- 収集する項目、送信先（AI 提供者、音声サービス）、保持期間を、初回に分かりやすく示す。
- 記録や解析の出力に、回答文の全文や個人を特定できる情報を出さない。

## 5. 端末の保存データ

| データ | 内容 | 壊れた場合 |
|---|---|---|
| 設定 | 画質、音量、操作 | 初期値に戻す |
| 進行の写し | 表示用 | サーバーから取り直す |
| 音声の一時保管 | 取得済みの音声 | 取り直す |
| 地域データ | 追加で取得した資産 | 取り直す |

端末だけに存在する重要なデータは作らない。機種変更や再インストールで失われないようにする。

## 6. データ量の目安（仮定）

| 項目 | 目安 |
|---|---|
| 1試練の記録（文字） | 数十 KB（監査記録を含む） |
| 1シナリオの音声 | 1〜3 MB（会話の長さと音質による） |
| 月180試練の利用者1人 | 文字で数 MB、音声の参照で数百 MB（音声は共有・期限付き） |

音声が容量の大半を占める。使用済みで参照されなくなった音声を定期的に消す仕組みを最初から入れる。
