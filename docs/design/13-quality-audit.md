# 13 品質監査報告

設計者とは独立した立場で、設計書 00〜12 の欠陥を指摘する。設計を擁護しない。指摘した欠陥は**設計書には反映していない**。直し方に設計判断を伴うものが多く、承認時の判断を仰ぐべきだからである。

## 1. 総合所見

**判定: 条件付きで、第2段階（文字だけの核心検証）に進むことは妥当。3D の制作に進むことは、現時点では妥当でない。**

設計は、公平性の仕組み（事前確定、検品、突き合わせ、引用の照合、2回評価、物言い）を厚く積んでいる。しかし、その仕組みが実際に働くことを示す実測は一つもない。目標値はすべて仮で、料金は仮定の積み上げである。設計書は「できること」を示したのではなく、「確かめるべきこと」を整理した段階にある。

第2段階に入る前に解決すべきものを §5 に示す。

## 2. 重大な欠陥

### 指摘1: 即失敗の公平性が、未検証の AI 判定に全面的に依存している

- 致命的なミス1回で試練が終わる。その判定を下すのは AI である。「誤って A とする割合 1% 未満」という目標には根拠がない。達成できるかは誰にも分からない。
- 1% でも、月180試練なら1人あたり月に1〜2回、正しく聞いたのに失敗させられる。厳しいゲームでは、1回の理不尽な失敗が信頼を壊す。
- 2回目の評価は同じモデルによる。同じ誤りを2回とも犯す可能性があり、独立性は限定的である。
- **勧告**: 正解集で基準を満たすまで、AI 判定による即失敗を有効にしない。満たせない場合の代替（[12](12-risks.md) R-01）を、代替ではなく初期の既定とすることを検討する。つまり、即失敗は実行型と値の照合で判定できる項目から始め、AI 判定の範囲は実績に応じて広げる。

### 指摘2: 料金が成り立つ見通しがない

- 仕様に最も忠実な構成で1試練 約 $0.8、月 約 $140。推奨案でも月 約 $50。これは一般的なゲームの価格と桁が合わない。
- しかもこの数字は、1文字 1.5 トークン、思考分の出力量、A 候補 30% といった仮定の上にある。思考分の出力は `effort` と課題の難しさで大きく変わり、数倍ずれてもおかしくない。
- 設計は「事業上の判断」として利用者に委ねているが、料金の解がなければ設計全体が成立しない。
- **勧告**: 第2段階の最初に実測する。個人利用か販売か（Q1）を先に決める。販売するなら、価格と利用回数の上限を先に置き、そこから逆算してモデルの構成を決める。

### 指摘3: 目標の画質と、制作の現実がつながっていない

- 「高品質で美しい和風3D」を5地域分作る素材の制作体制が、設計のどこにもない。Claude Code は素材を作れない。
- 設計は「構図と霧と音で見せる」と述べるが、それは方針であって計画ではない。
- 価値の中心は会話にあり、費用の中心は 3D にある。この不釣り合いは、設計書自身が認めながら（[12](12-risks.md) R-24）、範囲は5地域のまま縮めていない。
- **勧告**: 最小の製品範囲を定義する。例: PC のみ、1地域、話し手は数人、主の試練1つ。5地域は、縦切りの費用が分かってから決める。

### 指摘4: 受信の力が伸びるという根拠がない

- 現実の会話にない行為が、ゲームの中心にある。確度の印を付ける、宣言をする、固定の質問に答える。これらが上手くなることと、日常で話を正確に聞けることは別である。
- 罠の型は有限である。プレイヤーは型を覚え、「最後に条件が来る」と構えるようになる。これは受信の向上か、このゲームへの適応か、区別がつかない。
- 検証計画（[11](11-test-plan.md) §8）は最終段階に置かれている。効果がないと分かるのが、全制作費を使った後になる。
- **勧告**: ゲーム外の課題による効果の確認を、第2段階の文字だけの試作の時点で小規模に始める。

## 3. 設計内の矛盾・未定義

### 指摘5: 自由な申し送りで落とし、問い返しで思い出した場合の扱いが未定義

- [03](03-penalty-system.md) は、自覚のない欠落を「触れず、宣言し、問い返しでも『なかった』と答えた」場合と例示する。では、申し送りでは落として「以上ですべて」と宣言したが、問い返しで訊かれて正しく答えた場合はどうなるのか。規則表（[05](05-ai-evaluation.md) §5）にこの場合がない。
- 罰なしとすれば、申し送りは最小限にして問い返しを待つのが最善手になり、自由な申し送りが形だけになる。A とすれば、問い返しの意味がなくなる。
- **勧告**: 規則を定める。案: 最重要の項目を申し送りで落とし、問い返しで正しく答えた場合は B（促されて初めて伝えた）。

### 指摘6: 「食い違い」の罠と、「あいまいな出題で罰しない」が衝突している

- [05](05-ai-evaluation.md) §5 は、食い違いのある最重要の項目について、片方だけを事実として伝えたら A とする。しかし食い違いは、定義上あいまいである。後に言われた方を訂正と受け取るのは、不合理な聞き方ではない。
- これは [03](03-penalty-system.md) の F5（あいまいな出題で罰しない）と正面から衝突する。
- **勧告**: 食い違いの見落としは最大でも B とする。または、食い違いの罠では訂正と受け取れない形（別々の文脈で、どちらも断定）に限ると定め、検品で確かめる。

### 指摘7: 未達が、罰のない引き直しとして使える

- 最重要の項目を「不明」と申告すれば未達になり、灯火を失わずに別の会話に挑める。難しい会話に当たったら未達で流し、易しい会話を待つことができる。灯火による緊張が成り立たなくなる。
- 「迷ったら断定しない」は鍛えたい行動そのものなので、罰するのは筋が悪い。しかし無制限では仕組みが崩れる。
- **勧告**: 未達の後に出る会話は、同じ難易度・同じ罠の型の別シナリオに固定する。主の試練では、未達はその段のやり直しとする。

### 指摘8: 「記憶力ゲームではない」と、手順の順序が合っていない

- 手順は、会話 → 運ぶ（30〜90秒歩く）→ 整理、である。整理は歩いた後になる。難しい設定では、情報素片12個、会話4分、途中で妨害が入る。これは記憶の負荷である。
- 受信（聞いたときに正しく取り込めたか）と保持（覚えていられたか）が混ざり、失敗の原因を分けられない。
- **勧告**: 既定では、会話の直後にその場で整理する。運んでからの整理は上級の変化として扱う。失敗の分析で、受信の失敗と保持の失敗を区別できるかを検討する。

### 指摘9: 突き合わせの工程そのものが、検証されていない AI 判定である

- 会話後の突き合わせ（[05](05-ai-evaluation.md) §3）は、発話に裏付けがあるかを AI が判断する。「裏付けが弱い」の基準が定義されていない。
- この工程が誤って項目を有効と認めれば、言われていないことで罰することになる。評価役と同じ重さの検定が要るが、テスト計画に独立した項目がない。
- **勧告**: 突き合わせを検定の対象に加える。最重要の項目の裏付けは、読みをそろえた上での文字列の一致を基本とし、AI の判断は補助にとどめる。

### 指摘10: 聞き返しへの応答は、事前の公平性の保証の外にある

- 本筋は検品されるが、聞き返しへの応答はその場で作られ、その場で合成される。読み誤り、事実の表との食い違い、誘導の発言が起きても、事前には止められない。
- 設計は「関係する項目を無効にする」とするが、プレイヤーが誤った応答を信じて答えた場合、無効化だけでは救えない場面がある（誤った情報を事実として伝え、捏造と判定される）。
- **勧告**: 聞き返しの応答に由来する情報は、発話記録に応答が残っている限り、プレイヤーに不利な判定の根拠にしないと明記する。

## 4. その他の欠陥

| No. | 指摘 | 勧告 |
|---|---|---|
| 11 | **検品役は「聞く」ことを再現していない。** 文字を読む AI が解けても、耳で聞く人にはあいまいな場合がある（同音異義、区切り、抑揚） | 人が実際に聞いて確かめる抜き取り検査を、検品の工程に加える |
| 12 | **問い返しが引っかけに感じられるおそれ。** 言われていないことを訊かれるのは、訓練として妥当でも、理不尽と受け取られやすい | 導入で仕組みを明示する。受け手の人物設定として自然に見せる |
| 13 | **間合いが見えない。** 上限を表示しないため、計画が立てられず、突然断られたと感じる | 相手の様子による予告を必ず入れ、試験で伝わるかを確かめる |
| 14 | **応答型の評価基準があいまい。** 「話に沿った返答」は、伝達型より判断の幅が広い | 基準が定まり検定を通るまで、応答型では即失敗を出さない |
| 15 | **仕組みが多すぎる。** 3つの結果、3つの格、3つの印、灯火、間合い、追い稽古、物言い、稽古と本番、2つの方式。規則の理解が受信より難しくなるおそれ | 最小の範囲では、格と追い稽古を外す |
| 16 | **在庫方式が仕様の文言と合わない。** 「毎回生成する」に対し、事前生成の共有を推奨している。流出の対策も弱い | 設計者も論点として挙げている（Q2）。承認を得るまで採用しない |
| 17 | **個人利用なら、サーバー構成は過大。** 認証、在庫、利用量制御は、1人で使うなら要らない | Q1 の回答に応じて、2つの構成（個人用の簡易構成、製品用）に分ける |
| 18 | **話し方や声による不利。** 音声認識は、方言、発話の特性、機器によって精度が変わる | 検証用の録音に多様な話者を入れる。文字入力を対等な手段として扱う |
| 19 | **判定ゲートの基準が主観的。** 「面白い」「ほぼゼロ」「現実的」は、通過の可否を客観的に決められない | 第2段階の計画時に、数値と判定者を決める |
| 20 | **工程に期間と費用がない。** 実現性を判断できない | 体制の決定後に見積もる（設計者も明記している） |
| 21 | **法務の検討が浅い。** 音声、回答文、未成年、声の権利を一括りにしている | 対象地域と対象年齢を決めた後、専門家の確認を受ける |
| 22 | **検証が資料の確認にとどまる。** API の疎通、遅延、音声の品質は一度も実測していない。音声サービスの料金は第三者情報で、互いに食い違う | 設計者も明記している。第2・第3段階で実測に置き換える |
| 23 | **A の見逃し 10% を許容している。** 公平さを優先した結果だが、致命的な聞き違いの1割が通ることになり、訓練としての厳密さが下がる | 見逃しの実績を監視し、訓練効果への影響を確かめる |
| 24 | **造語が多い。** 聴き継ぎ、道行き、申し送り、問い返し、物言いなど | 画面上の用語は、試験で理解度を確かめて絞る |

## 6. 評価できる点

監査は欠陥の指摘が役目だが、判断の材料として、妥当と認める点も記す。

- 重要度を出題前に確定し、封印する仕組みは、仕様の要求を正しく満たしている。
- AI が事実を判定し、罰はプログラムの規則表が決めるという分離は、誤判定の影響を抑える正しい構造である。
- 3D の前に文字だけで核心を確かめる工程の順序は妥当である。
- 実行型の試練は、AI に頼らず客観的に判定でき、3D と受信を結び付ける。もっと中心に据える価値がある。
- 確認できたこと、第三者情報、未検証を区別し、できないことをできないと書いている。
