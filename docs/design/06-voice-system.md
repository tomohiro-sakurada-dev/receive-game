# 06 音声システム設計書

## 1. 前提

**Claude Fable 5.2 は音声を直接扱えない**（入出力はテキスト・画像・文書。[00](00-overview.md) §3.1）。したがって音声認識と音声合成は外部サービスで行い、Fable 5.2 とはテキストでやり取りする。

| 流れ | 経路 |
|---|---|
| 話し手の声 | 台本（テキスト、読み仮名付き）→ 音声合成 → 再生 |
| プレイヤーの声 | マイク → 発話区間の検出 → 音声認識 → テキスト → 画面で確認 → 確定 |

## 2. 求める声

| 希望 | 選定での確かめ方 |
|---|---|
| 透明感がある、美しい | 試聴による主観評価（複数人） |
| 少し低めで深みがある | 候補の声の中から、低めの声質を選ぶ |
| 落ち着いている | 抑揚の強さを調整できるか |
| 自然なイントネーション | **日本語の高低アクセントの正確さ**を、日付・数・固有名・同音異義語の文で確かめる |
| 長時間聞いても不快にならない | 30分以上の連続試聴での疲労評価 |

声の良し悪しは資料では判断できない。**候補を実際に聞き比べて決める**（§4）。現時点でどのサービスの声が希望に合うかは断定しない。

### 選定基準

1. 日本語の正確さ（§7 の検証で測る）
2. 遅延（話し終えてから確定の文が出るまで）
3. 逐次処理の可否
4. ゲーム固有の語（人名・地名）を登録できるか
5. 料金
6. 音声データの取り扱い（保存の有無、学習への利用）

### 認識の誤りを失敗にしない仕組み

- 申し送りと問い返しへの回答は、**認識結果を画面に示し、プレイヤーが確かめて確定する**。言い直しも、文字での修正もできる。評価するのは確定した文だけ。
- 会話中の聞き返しは即時に処理するので、確認の画面は挟まない。そのかわり、聞き返しの内容は罰の根拠にしない。認識の確からしさが低いときは、話し手が「もう一度言ってくれ」と返し、間合いは使わない。
- 初回起動時と設定画面で、マイクの調整を行う。周囲の音を測り、試しに数文を読んでもらい、認識結果を見せる。うまくいかない環境では、文字で答える方式を勧める。

| VOICEVOX | 無償・商用可・クレジット表記が条件。端末内やサーバーで動かせる | 希望の声質（落ち着いた低めの声）に合うか |

### 選定基準

1. 声質が希望に合うか（試聴）
2. 日本語の読みとアクセントの正確さ
3. **読みを指定できるか**（読み仮名、SSML、辞書）。公平性に直結する
4. 話す速さを指定できるか
5. 遅延（逐次再生の可否）
6. 料金
7. ゲームに組み込む利用条件、声の権利関係

### 声の選考の手順

1. 候補ごとに、希望に近い声を2〜3選ぶ。
2. 共通の試験文（日付、数、固有名、同音異義語、長い語り、感情を抑えた会話）を合成する。
3. サービス名を伏せて聞き比べ、§2 の観点で採点する。
4. 読み誤りの数を数える。
5. 上位を、30分の連続試聴で確かめる。
6. 主となる1社と、障害時の代替1社を決める。

### 合成の時機

| 対象 | 時機 |
|---|---|
| 台本の本筋 | **事前に合成**し、検品（§5）を通してから使う。遅延がなく、公平性を事前に確かめられる |
| 聞き返しへの応答 | その場で合成（逐次再生）。最重要の語は読み仮名で渡す |

## 5. 音声の検品（合成の誤りを失敗にしない）

日本語の音声合成は、数・日付・固有名・同音異義語を読み誤ることがある（「七日」「一日」「明日」など）。読み誤った音声で出題すれば、正しく聞いたプレイヤーを罰してしまう。

| 対策 | 内容 |
|---|---|
| 読み仮名の付与 | 最重要の語は、構成役が読み仮名を付ける。合成には読み仮名または読みの指定を渡す |
| 語彙表の管理 | 人名・地名は、読みが一つに定まり、互いに音の遠いものだけを登録する |
| 聞き直しによる検査 | 合成した音声を音声認識にかけ、最重要の語が意図した読みで認識されるかを確かめる。合わなければ合成し直す |
| 発話記録の正本 | 評価に使うのは「実際に流れた音声の内容」。検査で確かめた読みを記録する |

**限界**: 聞き直しの検査では、読みの誤りは見つかるが、高低アクセントの誤りは見つからない。アクセントの違いだけで意味が変わる語の組は、語彙表から外すことで避ける。聞き返しへの応答はその場で合成するため事前の検査ができない。応答で話した最重要の語は、再生と並行して検査し、不合格なら関係する項目を無効にする。

## 6. 発話終了の検出

プレイヤーが話し終えたことを判断する仕組みである。早すぎると発言が途切れ、遅すぎると会話が間延びする。日本語は「えーと」などの間が長い。

| 場面 | 方式 |
|---|---|
| 申し送り、問い返しへの回答 | **プレイヤーが自分で終える**（ボタン）。自動では打ち切らない。公平性を優先する |
| 会話中の聞き返し（既定） | **押している間だけ話す**方式。離したら終わり |
| 会話中の聞き返し（任意設定） | マイクを開いたままにする方式。無音の長さと、音声認識側の文末の判定を合わせて終わりを決める。無音の閾値は調整できる |

マイクを開いたままにする方式では、スピーカーから出た話し手の声をマイクが拾う問題がある。ヘッドホンの使用を条件にするか、端末の反響除去機能を使う。既定を「押している間だけ話す」にするのはこのためである。

発話区間の検出は端末内で行う（無音を送らないことで料金と遅延を減らす）。具体的な部品は試作で選ぶ。

## 7. 認識精度の検証

| 項目 | 内容 |
|---|---|
| 試験用の音声 | ゲームで実際に出る種類の文（日付、数、人名、地名、条件文、申し送りの形）を、複数の話者・機器・環境（静か、生活音、屋外）で録る |
| 指標 | 文字単位の誤り率。加えて、**重要な語（日時・人名・数）が正しく認識された割合** |
| 比較 | 候補のサービスを同じ音声で比べる |
| 合格の目安（仮） | 静かな環境で、重要な語の正解率 97% 以上。達しない環境では文字入力を勧める |
| 継続的な監視 | プレイヤーが認識結果を修正した割合を集計し、劣化を見つける |

## 8. 話速と試聴

- 設定で話す速さを選べる（目安 0.8〜1.2倍）。これは聞き取りやすさのための設定で、難易度ではない。
- 話し手の性格による速さの違い（早口など）は、設定した速さを基準に ±15% の範囲に収める。
- 事前に合成した音声の速さを変える方法は2つある。速さ別に合成しておく（料金が増える）か、端末側で音の高さを変えずに伸縮する（品質の確認が要る）。試作で決める。
- 声の選択画面で、候補の声を試聴して選べる。選んだ声は語り手や受け手などに適用する。話し手ごとの声は、性格に合わせて複数用意する。

## 9. 遅延の目標（仮。実測で確定）

| 区間 | 目標 |
|---|---|
| 台本の本筋の再生開始 | 即時（事前合成） |
| 聞き返しを終えてから、話し手の声が出るまで | 2.5秒以内。話し手の「ふむ」などの短い声で間を埋める |
| 申し送りの確定から判定まで | 15秒以内。受け手が黙って考える演出で待つ |

これらが達成できるかは**未検証**である。特に Fable 5.2 の応答開始までの時間は実測が必要（[10](10-roadmap.md) 第2段階）。

## 10. 音声データの扱い

- プレイヤーの音声は、音声認識サービスに送られる。この点を初回に明示し、同意を得る。
- 既定では、プレイヤーの音声そのものは保存しない。保存するのは確定した文だけ。
- 精度検証への協力として音声を提供するかは、任意の選択にする。
- 採用するサービスは、送った音声を学習に使わない設定ができるものを優先する。
