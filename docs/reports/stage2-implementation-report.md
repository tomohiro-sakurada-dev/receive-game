### ゲームの流れ（実装したもの）

1. 結び灯籠で、地と灯火を確かめる。
2. 話し手の話を聴く。言葉は一度きりで消える。話の終わりは自分で確かめる。
3. 必要なら聞き返す（回数に限りがある）。
4. 八つの欄に、確度の印と中身を書く。ここからも話し手に確かめに戻れる。
5. 受け手の言い換え3問に答える。
6. 判定。誤りごとに、話し手が実際に言った言葉、自分が渡した言葉、手本、理由が並ぶ。
7. 別の話で次の試練へ。

### 画面の作り（Unity 側）

題字、心得、結び灯籠、会話、整理、申し送り、判定、聴き帳の8画面。背景は起動時に計算で描く（夜空、月、三重の山並み、流れる二層の霧、ゆらぐ灯火、縁の暗がり）。成就すると霧が薄れ、歪むと画面が白んで霧が濃くなる。題字と判定は縦書き。和文は明朝体を同梱した。**これらは意図した設計であり、実際の見え方は未確認である。**

## 3. テスト結果

実行: `dotnet test dotnet/Receive.Tests`（.NET SDK 8.0.134、NUnit 3.14）。**60 件すべて成功、失敗 0。** 全件の一覧は `test-results-2026-11-15.txt`。

指示された検証項目との対応:

| 検証項目 | テスト（抜粋） | 結果 |
|---|---|---|
| 正しい回答 | 正しい回答は成就し罰がない／どのシナリオも最後まで聞いて確かめれば成就できる（2,000 本） | 成功 |
| 重要情報の聞き漏らし | 最重要の条件を言われていないとすると聞き漏らしで歪みになる／重要度が中の欄の聞き漏らしは灯火を1つ減らすだけ | 成功 |
| 情報の一部だけを誤認 | 日だけを取り違えると日だけが誤認になり他は正しいまま／ただし書きの片方だけ違うときは原因が記録される／言い直す前の値を答えると早合点として記録される | 成功 |
| 根拠のない推測 | 言われていないことを聞いたこととして渡すと根拠のない断定で歪みになる／推し量りは軽微にとどまる／推測や伝聞を確かなこととして渡すと根拠のない断定になる | 成功 |
| 不明の適切な申告 | 分からないと正直に申告すれば罰はなく未達になる／同じ欠落でも申告と聞き漏らしは別の種類として記録される | 成功 |
| 適切な聞き返し | あいまいな言葉を確かめなければ未達、確かめれば成就／先に訊くと先走りになる／間合いが尽きると答えてもらえない | 成功 |
| シナリオの重複 | 出題済みのシナリオは二度と出ない（600 本連続）／種が違えば内容はほぼ必ず違う | 成功 |
| 評価基準と正解データの整合性 | 評価データは台本の言葉と一致する（2,000 本）／封印は評価データが1つでも変わると変わる／出題内容は評価データを持たない／出題後に評価データが変わっていたら無効になり罰は出ない | 成功 |
| AIなしでの動作 | 通信もAIも使わずに道行きを最後まで遊べる／中核は通信やUnityの部品を参照していない | 成功 |

そのほか: 歪曲（受け手の言い換えへの同意、自分の申し送りを覆す）、技能が別々に数えられること、AI 由来の指摘が致命的にならないこと、すべての指摘に実際の言葉の引用が付くこと、道行きと灯火の規則、記録の保存と読み込み。

### 実プレイの記録

`playthrough-terminal.txt` に、端末版で同じ会話を3回遊んだ全文がある。

| 遊び方 | 結果 | 技能の記録（抜粋） |
|---|---|---|
| 最後まで聞き、そのまま申し送る | 成就（明鏡） | すべて満点 |
| ただし書きを「分からない」と申告 | 未達。罰なし。「不明の申告」と表示 | 最後まで聞く 1/2、分からないと知る 4/4 |
| 途中で切り上げ、ただし書きを「言われていない」とする | 歪み。「聞き漏らし〔致命〕」と表示、原因は切り上げ | 最後まで聞く 0/2、分からないと知る 3/4 |

### テスト中に見つけて直した不具合

| 不具合 | 対処 |
|---|---|
| 端末版が、入力が尽きると終了せず空回りした | 入力が閉じたら終了するようにした |
| 一部のシナリオで問い返しが2問しか作られなかった | 常に3問そろえるようにし、テストに加えた |
| 「今日に頼みたいのだ」という不自然な言い回し | 「頼みたいのは今日だ」に直した |
| 追い声のある話で、結びの言葉の後の聞き返しが「先走り」と記録された | 結びの言葉を聞いた後は先走りにしない |

## 4. Unity について未確認の点

Unity Editor で開いて確かめる必要がある。上から順に、起きた場合の影響が大きい。

| No. | 未確認の点 | 起きうること | 対処の見込み |
|---|---|---|---|
| U1 | Unity 6.3 でコンパイルが通るか | 検査は Unity 2021.3 の参照アセンブリで行った。6.3 で廃止・変更された API があれば、エラーで再生できない | エラーの箇所を直す。使った API は UI Toolkit の基本的なものに絞ってある |
| U2 | エディタ用スクリプト（`ReceiveProjectSetup.cs`）がコンパイルできるか | **このファイルだけはコンパイル検査もできていない**（エディタの参照アセンブリが入手できなかった）。エラーなら再生できない | エラーが出たら、このファイルを消せば再生できる（シーンと URP は手で用意する） |
| U3 | パッケージの版 | `manifest.json` の URP `17.3.0`、Test Framework `1.4.5` が解決できない可能性 | Package Manager で、その Editor に合う版を選び直す |
| U4 | URP の設定の自動作成 | URP の内部処理を名前で探して呼んでいる。版によって見つからない | Console に手作業の手順が出る。ゲームは URP の設定がなくても動く |
| U5 | 画面の見え方 | 配置の崩れ、文字のはみ出し、色や霧の濃さが意図と違う。一度も描画を見ていない | 見てから調整する。大きさは 1920×1080 を基準に手計算で決めた |
| U6 | 和文フォントの表示 | 同梱フォントが UI Toolkit に正しく渡らず、文字が出ない・豆腐になる | フォントの指定方法を変える |
| U7 | 一文字ずつ現す表示 | 未表示の文字を透明色のタグで隠している。タグがそのまま表示される可能性 | 別の隠し方に変える |
| U8 | 実行時に作った `PanelSettings` と既定テーマ | テーマが読めず、スクロール部分の見た目が崩れる | テーマの読み込み方を変える |
| U9 | 入力の設定 | 新しい Input System だけを有効にした設定では、クリックが効かない可能性 | Project Settings の Active Input Handling を「Both」にする |
| U10 | 起動用シーンの自動作成、ビルド | 未確認。ビルドは試していない | メニュー「RECEIVE」から作り直す |
| U11 | スマートフォン | 未対応。画面は 16:9 の横長を前提にしている。タッチでも押せる大きさにはしてある | 第6段階 |

`.meta` ファイル、`ProjectSettings/` の中身、起動用シーン、URP の設定ファイルは、Unity が初回に生成するため、まだリポジトリにない。

## 5. 既知の制約（Unity とは別に）

| 制約 | 内容 |
|---|---|
| 回答は選択式 | 語彙一覧から選ぶ。自分の言葉での申し送りではない。思い出す負荷が軽い（判断記録 A2） |
| 文の型が有限 | 数十回遊ぶと言い回しに既視感が出る。内容の組み合わせは重複しない |
| 訓練効果は未実証 | 記録できるのはゲーム内の成績だけ。日常の聞く力が伸びるかは分からない |
| 面白さは未検証 | 人が遊んで確かめていない。厳しさ（言われていないことを「聞いた」とすると全欄で即失敗）が妥当かも未検証 |
| 音声なし | 第3段階 |
| 未実装 | 主の試練、応答型・実行型の試練、弱点に合わせた出題、物言い、追い稽古、食い違いの罠、運ぶ過程 |
| 未達での引き直し | 難しい話を未達で流す抜け道が残っている（判断記録 A7） |
